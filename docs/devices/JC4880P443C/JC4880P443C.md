# JC4880P443C-I-W (Shenzhen Jingcai Intelligent)

4.3" ESP32-P4 + ESP32-C6 MIPI-DSI touch display module.
Datasheet in this folder: `JC4880P443C_I_W Specifications-EN-V1.0.pdf`.
Vendor reference repository: https://github.com/wegi1/ESP32P4-JC4880P443C-I-W

## Camera

MIPI-CSI interface. The vendor repository ships the **OV02C10** (2 MP) sensor datasheet, so
that is the intended camera. The CSI data lanes and SCCB pins are not documented in the spec
PDF - check `5-Schematic/2_LCD&CSI.png` in the vendor repo. The reference implementation used
by the vendor demos wires the CSI SCCB to SCL 8 / SDA 7 (shared with the touch bus).

## Audio

| Item | Value |
|---|---|
| Codec | ES8311 (I2C address 0x18) |
| Amplifier enable | GPIO 11 (PA) |
| Amplifier | NS4150 (from a Google AI summary quoted on Reddit, 2026-10-09; not checked against the schematic, `5-Schematic` of the vendor repo) |
| I2S MCK | 13 |
| I2S BCK | 12 |
| I2S WS / LRCK | 10 |
| I2S DOUT | 9 |
| I2S DIN | 48 |
| I/O | microphone input + speaker output |

In this project (2026-10-09): the codec answers at 0x18 on the touch bus (SDA 7 / SCL 8); set up
with `esp_codec_dev` as an I2S slave with MCLK = 256 x the sample rate from the P4, 16 bit, DAC at
0 dB; the amplifier on GPIO 11 is switched with the output (`components/board/boards/jc4880p443c/
es8311.cpp`). The microphone is not used.

- `esp_codec_dev`'s stop writes 0 to the DAC volume (REG32) and its start does not restore it: the
  firmware sets the volume on every start.
- Power: at the DAC's full scale a loud sound restarts the board ("power on" reset; 70 % volume
  of a 500 Hz tone did, 50 % did not, also on a USB hub with 10 W). The DAC runs at -12 dB
  (`kDacDb`): all sounds at 100 % play without a restart (2026-10-09). The board recommends a
  5 V supply of 2 to 3 A; it ran on USB (0.5 A from a PC port). Discuss with the developer before
  raising `kDacDb` or lowering it further: test with a proper supply first
  (docs/adding-a-board.md, "Power"). A worn USB cable also restarted it at random.
- The same AI summary says the amplifier, the codec and a camera module (OV02C10, OV2640) draw
  current in spikes, and recommends a supply of 1.5 to 2 A for loud audio or a camera, against
  brownouts. Unverified, but it matches what was measured: the speaker restarted the board on USB
  (0.5 A). Keep it in mind for the camera.

## This project (esp32-hassctrl)

Board `jc4880p443c`: `boards/jc4880p443c/sdkconfig.defaults`,
`components/board/boards/jc4880p443c/jc4880p443c.cpp`. Brought up on COM11 on 2026-10-08 (the
vendor demo on the flash is gone).

| Item | Verified |
|---|---|
| Chip | ESP32-P4 rev v3.2, 400 MHz, PSRAM in the chip: 32 MB hex (AP, generation 4), 200 MHz |
| Flash | 16 MB, manufacturer 0x68 / device 0x4018: Boya (`CONFIG_SPI_FLASH_SUPPORT_BOYA_CHIP`), QIO |
| USB | port "USB2" = USB-Serial/JTAG of the chip (`303A:1001`): console and log on it |

| Display path | `Info::mipi_dsi`: esp_lvgl_port's DSI display, two 50-line draw buffers in internal RAM, LVGL software rotation |
| Touch | GT911 at 0x5D on SDA 7 / SCL 8, 100 kHz, polled |
| Backlight | GPIO 23, LEDC 25 kHz, minimum duty 9 of 1023 (user, 2026-10-08) |
| Wi-Fi | ESP32-C6 over SDIO (slot 1, 4 bit, 40 MHz, CLK 18, CMD 19, D0..D3 14..17, C6 reset GPIO 54) with `esp_hosted` 3.0.9 + `esp_wifi_remote` 1.6.5 on both chips (C6 updated 2026-10-08) |

| Sizes | main firmware 1.91 MB, recovery app 953 KB of 1 MB (7 % free) |
| Redraw | full screen 50-55 ms at 90 degrees (LVGL software rotation + DMA2D copy), 2026-10-08; with the CPU copy and a rotation buffer of 48 KB about 50 ms, no tearing (checked by the user) |

USB ports (schematic `5-Schematic/4_USB&IO.png`): "USB2" is the P4's full-speed USB
(USB-Serial/JTAG, flashing and console), "USB3" the P4's high-speed USB OTG. Neither reaches the
C6. The C6's UART is only on the expansion header JP1: pin 20 `C6_U0RXD`, 22 `C6_U0TXD`, 24
`C6_IO9` (boot strap, low = download mode), 26 `C6_CHIP_PU` (reset). The vendor ships the C6
firmware as `8-Burn operation/Burn files/JC-C6-slave_v2.3.2.bin`.

### C6 firmware

The C6 came with the vendor's esp_hosted 2.3.2 (IDF v5.5, `JC-C6-slave_v2.3.2.bin`, a full 4 MB
flash image: ota_0 and ota_1 of 1.5 MB each). Against the 3.0.9 host it logged "major version
mismatch", and the first connection after a reset often hung in "connecting". Since 2026-10-08
it runs our build of esp_hosted 3.0.9, `boards/jc4880p443c/c6` (the coprocessor of esp_hosted's
`examples/ota/coprocessor_ota/cp`, Wi-Fi only, the vendor's partition table): versions match,
SDIO SW_AGGR is negotiated, Wi-Fi connects on the first try.

The update goes over the SDIO link, no cable on the C6 (the C6's old bootloader boots apps of
newer IDF versions; a broken image is refused at the end and the C6 stays on its firmware):

```powershell
idf.py -C boards/jc4880p443c/c6 -B build/jc4880p443c/c6 set-target esp32c6 build
python -m http.server 8765 --bind <PC address> --directory build/jc4880p443c/c6
# device console
c6 version
c6 update http://<PC address>:8765/hassctrl-c6.bin
```

After the image is written the P4 restarts, which resets the C6 into the new firmware. When the
host side's esp_hosted version changes (dependencies.lock), pin the same version in
`boards/jc4880p443c/c6/main/idf_component.yml` and update the C6 again.

Checked by the user (2026-10-08, docs/adding-a-board.md steps 4 to 6): colors correct (RGB, no
inversion), no tearing with partial refreshes into the scanned frame buffer, software rotation
in all orientations with touch under the finger, minimum backlight duty 9.

Known on 2026-10-08:

- Every boot logs `esp_lcd_panel_swap_xy: swap_xy is not supported by this panel`: esp_lvgl_port
  applies the start rotation once even with software rotation, and the DPI panel has no
  swap_xy. Harmless.

## Vendor material

From [wegi1/ESP32P4-JC4880P443C-I-W](https://github.com/wegi1/ESP32P4-JC4880P443C-I-W):

- `1-Demo/idf_examples/ESP-IDF`: ESP-IDF 5.5 demos with a modified ESP32-P4 Function EV board BSP;
  its `esp_lcd_st7701_mipi.c` holds the init table and its DPI timing
  (`ST7701_480_360_PANEL_60HZ_DPI_CONFIG`) used by this project. The `sdkconfig` there gives the
  esp_hosted SDIO pins.
- `1-Demo/arduino_examples`: Arduino (arduino-esp32 3.2.1) demos with LVGL 8 and 9; the LVGL 9
  one rotates in software, as this project does.
- `5-Schematic`: the schematic (USB ports and expansion header: `4_USB&IO.png`).
- `8-Burn operation/Burn files`: the vendor's P4 demo images and the C6 firmware
  `JC-C6-slave_v2.3.2.bin` (full 4 MB flash image, the way back to the vendor C6 firmware: flash it
  over the C6 UART on header JP1).
